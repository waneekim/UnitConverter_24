# UnitConverter_XX — Mom Test 기반 세션 워크북

**근거:** [Report/mom-test-report.md](./mom-test-report.md) · [Prompt/mom-test-prompt.md](../Prompt/mom-test-prompt.md)  
**대상 코드:** `UnitConverter.py` (meter / feet / yard, `단위:값` 단일 입력)

---

## 1) 주제 (1문장)

> **도면의 피트·인치 치수(예: `3'-6"`)를 발주·견적용 단위로 오환산 없이 변환하는 규칙과, Mom Test에서 드러난 착각·반복·단위 혼동 손실을 Test Loop로 재현·고정한다.**

*(솔루션 최소화 — "변환 CLI·앱·일괄 프로그램"이 아니라 **환산 판정 오류·반복 비용·단위 혼동**만 다룸)*

---

## 2) R-G-I-O

| | 내용 |
|---|---|
| **R — Role** | 건축 현장·사무실에서 **도면(피트·인치)** 치수를 **발주서·견적서(미터·소수 feet 등)** 용으로 바꿔야 하는 건축업자. 현장은 계산기·메모, 사무실은 엑셀·CLI(거의 미사용) |
| **G — Goal** | 피트·인치 → 목표 단위 변환 시 **소수 feet 착각(3.5 vs 3.75)·야드/피트 혼동·치수별 반복 입력**으로 새는 **시간(15분·10분·3~4분)과 비용(3만 원)** 을 줄인다 *(Mom Test 손실 → 처음·한 번에)* |
| **I — Input** | 치수 문자열 1개 또는 목록. 예: `"3'-6""`, `"9'-2""`, `"feet:3.5"`, `"meter:2.5"`, `["3'-6"", "9'-2"", …]` (8개 철골 치수 등) |
| **O — Output** | `convert_length(spec)` 또는 `convert_lengths(specs[])` → **ConversionResult**: 입력 표기, **정확한 소수 feet**, meter / feet / yard 변환값, (선택) 견적용 **반올림** 값. 오입력 시 **명확한 fail** (콜론 누락·알 수 없는 단위) |

---

## 3) 성공 기준 3개 (Mom Test 증거 연결)

| # | 성공 기준 | 연결 증거 |
|---|-----------|-----------|
| 1 | **`3'-6"`** 입력 시 **3.75 feet**(= 6인치는 0.5피트)로 파싱·변환한다. `feet:3.5`로 처리하면 **fail** 또는 테스트에서 **Red**로 잡힌다 | *"3피트 6인치는 3.5피트가 아니다"* — `feet:3.5` 오입력 → 발주서 수정 **15분** (지난 화요일) |
| 2 | **야드·피트** 변환 Rule이 명확하고, 동일 입력에 meter / feet / yard 결과가 **일관**된다. Test Loop **Green**으로 정답 수량을 고정한다 | *"긴급 재주문하면서 배송비 **3만 원**"* — 야드/피트 착각 오발주 (지난달) |
| 3 | 치수 **N개**를 **한 Command**(`convert_lengths`)로 처리해 N회 CLI 실행·엑셀 수동 입력과 같은 반복 비용을 줄인다. Red: 8개 중 1개 오환산 → fail assert; Green: 8개 일괄 정답 | *"치수 **8개**를 엑셀에 일일이… **10분**"* — 프로그램 1회 1개 → 8번 실행 부담 (지난주 금요일) |

## 4) 표면 문제 — 이번 프로젝트에서 하지 않을 것

| 하지 않음 | 이유 (Mom Test) |
|-----------|-----------------|
| **"건축업자용 단위 변환 CLI 프로그램을 만든다"** | 사용자는 **앱**을 요청하지 않음. 고통은 **환산 착각·반복·혼동** |
| **"피트·인치 지원 변환기 UI/앱"** 전체 | 표면 솔루션 — 이번 범위는 **파싱·변환 Rule + Test Loop** |
| **"한 번에 여러 치수 변환 프로그램"** (제품 포장) | 니즈는 **일괄 처리 Command**이지 새 **프로그램** 정의가 아님 |
| **"소수점 반올림 변환 앱"** | 견적용 반올림은 **출력 Rule** 수준; 별도 앱 아님 |
| README **전체** (OCP 리팩터, JSON/YAML 설정, 동적 단위 등록, CSV/JSON 출력) | Mom Test·세션 3 범위 밖 — **Rule · Command · Test Loop** 우선 |
| 현장용 **스마트폰·터미널 UX** 개선 | 인터뷰: 현장은 **계산기** 사용, CLI **한 달 1회** — UX는 후속 |
| inch를 **단독 `inch:값`** 만 추가하고 `3'-6"` 파싱은 안 하는 것 | 도면은 **`3'-6"`** 표기 — **건축 표기 파싱**이 핵심 |

## 5) 8계층 — 이번 세션에서 만들 것만

| 계층 | 세션에서 할 일 | Mom Test 연결 |
|------|----------------|---------------|
| **Rule** | **R1** — `X'-Y"` → 소수 feet = X + Y/12 (`3'-6"` = **3.75**, 3.5 아님). **R2** — meter 기준 feet↔yard 비율 고정, 단위 혼동 방지. **R3** — 견적용 출력 소수 자릿수(선택). **R4** — `단위:값` / 건축 표기 / 목록 입력 형식 검증 | *"3.5피트가 아니다"*, *"야드/피트 착각"*, *"소수점 8자리 → 3~4분"* |
| **Command** | `convert_length(spec: str) -> ConversionResult` — 단일 치수 파싱 + 변환. `convert_lengths(specs: list[str]) -> list[ConversionResult]` — **8개 치수 1회** 처리 | *15분* 발주 수정 → **한 번에 정확한 feet/meter**; *10분* 엑셀 → **목록 1 Command** |
| **(Skill)** | *(선택)* pytest + Mom Test **Red/Green fixture** (`3'-6"`, 8개 철골 치수, yard/feet 혼동 케이스) 준비 Skill | 매번 수동 환산·엑셀 반복 제거 |
| **Test Loop** | **Red:** `3'-6"` → 3.5 feet 취급 시 fail; **Red:** yard/feet 혼동 케이스 fail; **Green:** `3'-6"` → 3.75 ft + 정확 meter; **Green:** 8개 치수 fixture 일괄 pass | *15분·3만 원·10분* 손실 → **같은 실패·성공을 자동 재현** |

**이번 세션에서 만들지 않음:** Harness 전체 리팩터(OCP/SRP), 설정 외부화, 동적 단위 등록, JSON/CSV CLI, 현장 UI, "변환기 앱" 포장

## 참고 — 진짜 문제 (보고서 §2)

> 도면에 **피트·인치**로 나온 치수를 발주·견적용 단위(미터 등)로 바꿀 때, **소수 피트 환산 착각·단위 혼동·치수별 반복 입력** 때문에 시간이 새고, 잘못된 수량 발주로 **비용**이 발생한다.
