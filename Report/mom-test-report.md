# Mom Test 인터뷰 보고서 — 길이 변환 CLI

**인터뷰 일자:** 2026-06-11  
**페르소나:** 건축 현장·사무실에서 도면·견적·발주 시 단위 변환이 필요한 건축업자  
**대상 제품:** `UnitConverter.py` (meter / feet / yard, `단위:값` 단일 입력 CLI)

---

## 1. 표면 문제 (잘못된 정의)

- "건축업자용 **단위 변환 CLI 프로그램**을 만든다."
- "**피트·인치를 지원하는 변환기**를 만든다."
- "**한 번에 여러 치수**를 변환하는 프로그램을 만든다."
- "**소수점 반올림**이 되는 변환 앱을 만든다."

→ 위 표현들은 모두 **솔루션(만들 것)** 을 먼저 정의한 것이다. 인터뷰에서는 사용자가 이런 것을 요청하지 않았다.

---

## 2. 진짜 문제 (한 문장)

도면에 **피트·인치**로 나온 치수를 발주·견적용 단위(미터 등)로 바꿀 때, **소수 피트 환산 착각·단위 혼동·치수별 반복 입력** 때문에 시간이 새고, 잘못된 수량 발주로 **비용**이 발생한다.

---

## 3. Mom Test 증거 3줄

1. > "3피트 6인치는 3.5피트가 아니다" — `feet:3.5`로 넣어 발주서를 잘못 썼고, 확인·수정에 **15분** 소요 (지난 화요일)
2. > "긴급 재주문하면서 배송비 **3만 원**을 추가로 냈습니다" — 야드/피트 착각으로 수량 오발주 (지난달)
3. > "치수 **8개**를 엑셀에 일일이 넣어서 변환했어요. 그때 **10분**" — 프로그램은 한 번에 하나만 되어 8번 실행이 부담되어 엑셀 선택 (지난주 금요일)

## 인터뷰 요약 (워크북 전체)

### Q1. 단위 변환할 때 가장 최근에 곤란했던 일이 뭐예요?

지난 화요일 오후, 2층 복도 벽체 마감 도면에서 문 개구부 폭 **3'-6"** 을 미터 발주서에 넣으려 `feet:3.5` 입력. 6인치를 0.5피트로 잘못 환산(실제 3.75피트). 현장 반장 확인 후 발주서 수정까지 **15분**, 해당 문 개구부 발주 **두 번** 확인.

### Q2. 지금 단위 변환은 어떻게 하세요?

- **현장:** 스마트폰 계산기 + 종이 메모의 변환 비율(1피트=0.3048m). PC/터미널 거의 미사용.
- **사무실:** 엑셀 수식(`=A2*0.3048`)으로 일괄 변환. 지난주 금요일 철골 치수 8개 → **10분**.
- **이 CLI:** 한 달 전 1회 사용 후 미사용. `meter:2.5` 콜론 형식 비익숙, 한 번에 하나만 변환.

### Q3. 이 프로그램 써본 적 있어요? 있으면 언제, 뭐가 불편했어요?

- **한 달 전:** `meter:3.2` → `10.49868784 feet` 등 소수점 과다. 견적서 반올림에 **3~4분** 추가.
- **지난 화요일:** `3'-6"`을 `feet:3.5`로 입력 → **15분** 손실.
- **기타:** 콜론 누락 시 에러(**2분**), inch 미지원, 1회 실행 후 종료.

### Q4. 돈이나 시간 날린 적 있어요?

| 유형 | 사건 | 손실 |
|------|------|------|
| 시간 | 3'-6" 환산 오류·발주서 수정 | 15분 |
| 시간 | 철골 치수 8개 엑셀 변환 | 10분 |
| 시간 | 소수점 반올림 | 3~4분 |
| 비용 | 야드/피트 착각 재주문 | 배송비 3만 원 |
| 빈도 | 시간 손실 | 주 1~2회 |
| 빈도 | 비용 손실 | 월 1회 꼴 |

### Q5. 인치(inch)는요? 현장에서 안 쓰세요?

매일 사용. 도면·줄자 모두 피트·인치. `3'-6"`, `9'-2"`, `4½"` 등. inch 미지원으로 소수 피트 수동 환산 중 착각 빈발.

### Q6. 한 번에 여러 치수 변환할 때는요?

- **지난주 금요일:** 치수 8개 → CLI는 8회 실행 예상(5분+) → 엑셀 선택(**10분**).
- **한 달 전:** 벽 길이 5군데 중 2~3개만 CLI, 나머지 계산기. 치수당 **~1분** 부담.
- 도면 보며 왔다 갔다 하며 **한 줄씩**만 나오는 출력이 비효율.
