## 1. 표면 문제 (잘못된 정의)

- "건축업자용 **견적 반올림 CLI**를 만든다."
- "**분수 인치 지원 변환기**를 만든다."
- "**8개 치수 일괄 입력 UI** 프로그램을 만든다."
- "**소수점 깔끔하게 나오는 앱**을 만든다."
- "**GUI 화면 있는 변환 프로그램**을 만든다." ← cmd 대체 **솔루션**

→ 솔루션을 먼저 정의한 표현. 인터뷰에서는 **표기 공백·출력 정리·반복 비용·cmd 사용 부담**만 드러남.

---

## 2. 진짜 문제 (한 문장)

도면의 **피트·인치·분수 인치** 치수를 발주·견적 단위로 옮길 때, **지원되지 않는 표기·과도한 출력·치수별 반복 실행·cmd 창 사용 부담** 때문에 여전히 수동 환산·엑셀·동료 확인으로 시간이 새고, 그 과정에서 **환산 착각과 오발주 비용**이 이어진다.

*(1차 핵심 — 소수 feet 착각·단위 혼동·반복 입력 — 은 유지되며, Round 2에서 **CLI↔API 갭·분수 표기·cmd 회피**가 추가 증거로 확인됨)*

3. > "철골 **8개** — cmd **8번** vs 엑셀 **8분** — 또 엑셀 썼다" (어제)

## 4. 인터뷰 요약

### Q1. 최근 곤란

`4½"` 단독 표기 → CLI 거부 → 계산기·동료 확인 **15분**.

### Q2. 현재 변환 방식

현장 계산기 / 사무실 엑셀. CLI는 `3'-6"` 성공 경험 있으나 **cmd 검은 화면에서 뭘 칠지 망설임·시행착오**(10분+)와 글자·복붙·영어 에러로 출력 정리·일괄은 여전히 엑셀 우선.

### Q3. 프로그램 사용 경험

정수 건축 표기는 개선 체감. 분수 인치·과다 소수·단건 종료·**cmd 검은 화면 타이핑 망설임·여러 번 오입력**은 불편 지속.

### Q4. 손실

시간 15분·8분·**10분+(cmd 망설임·시행착오)**·5분·2분·3~4분 (주간 반복). 비용 3만 원 (1차 사건, 월 1회 꼴). cmd 회피 **주 2~3회**.

### Q5. 인치

매일 사용. **분수 인치만** 적힌 도면이 빈번 — 미지원 구간.

### Q6. 여러 치수

8개 → **cmd 8회** 부담 → 엑셀 8분. API 일괄 기능 인지 없음.
